# Canaries

Automated probes that exercise the full request → *arr push chain for
each major content type. Each canary makes a request via the real
user-facing API (Seerr), then polls Seerr until the request's
`media.externalServiceId` is populated (= Seerr successfully reached
the *arr inside its container netns) and confirms that id matches the
*arr's record.

This forces traversal of the same Docker boundary that the
[reference_ucc-docker-host-loopback] bug class lives on. Earlier
host-side probes (`curl 127.0.0.1:17027/...` from the seedbox shell)
stayed green for ~9h on 2026-05-11 while every Seerr→Radarr request
was failing with `ECONNREFUSED 127.0.0.1:17027` inside Seerr's
container — that's the blind spot this rewrite closes.

The probe is non-destructive: the seed is the lowest-id movie/series
already in the *arr, so Seerr ack's via existing record. The Seerr
request itself is deleted in cleanup; the *arr movie/series is
untouched. On 409 (already-requested), the probe re-uses the existing
request id and skips the cleanup step.

Three predicates: heartbeat age vs a measured 336 h cap (71 real inter-run gaps: max 275 h, p95 102 h; false fires 72 h→6, 168 h→1, 336 h→0), verdict staleness while REA is still reaching the box, and the recorded outcome of the last run. An unrecognised outcome token fails **CLOSED** (exit 2). The **writer half** is `Get-LastTerminalAuditLine` + a base64 template hole in `Get-RemoteHeredoc`, wired into the gitignored `qflix-rea.ps1` and verified live **2026-08-03** (exit 2 → `PASS … reached=0h-ago verdict=6h-old`); it base64-encodes the previous run's terminal audit line so an `ssh_fail` message full of quotes and backticks can never be shell-interpolated, and it sits at the **end** of collection so every path that dies before the fetch — `tunnel_timeout`, `ollama_down`, `no_models`, `SKIPPED`-on-lock — writes nothing at all and lets the age predicate bite. Because that file is gitignored, losing or rolling it back is silent everywhere else: this canary is what says so, returning to exit 2 with `STAGE=rea-heartbeat-absent` rather than a silent pass on absence.

RLIMIT_NPROC counts every task, so a Go app defaulting GOMAXPROCS to the host's 128 cores can exhaust it and crash-loop on `pthread_create` EAGAIN — invisible until something dies (the 2026-06-26 VictoriaLogs class).
- `tdarr-scanner.sh`      — Tdarr's four startup scanner self-tests. Reds only on a **regression** in the load-bearing pair (FFprobe / Exiftool — without them Tdarr cannot read a file at all); the known-dead Mediainfo (WebAssembly OOM vs the slot's `ulimit -v` 10GB, unfixable) and CCExtractor (missing `libtesseract.so.4`) stay green-with-WARN instead of parking a permanent red on an accepted condition.
- `tdarr-pause-integrity.sh` — whether the fair-use quiet-hours PAUSE is actually **held**. tdarr-node is deliberately stopped 18:00–23:00 UTC so transcoding does not compete with the streaming peak, and every surface that could notice the pause FAILING is blinded during exactly that window *by design*: `pusher.py` sees `suppression.in_pause_window()` and pushes "Tdarr Node" **up** with `[paused: fair-use quiet hours]`, skipping probe and recovery outright (without which it auto-healed the node ~2 min into every pause — the 2026-06-12 false-recovery bug), and `tdarr-healthcheck.sh` holds its stall threshold *above* the 5 h pause so an idle node does not read as wedged. Net effect: a disabled, masked or rebuilt-away `tdarr-node-pause.timer` let the node transcode straight through the peak with **every monitor green**, and the pause half had no dead-man of its own — a stuck-PAUSED node eventually reds when the window closes, a stuck-RUNNING one never does. This asserts the missing direction: inside the window, the node must be **INACTIVE**. The window is **read from `manifest/apps.yaml`'s `pause_window`**, never restated — that number already lives in `lib/suppression`, `50c-tdarr-quiet-hours.sh`'s `OnCalendar` and the heartbeat guard, and a fourth copy is how it drifts. Semantics match `manifest.PauseWindow.contains` exactly: `[start, end)`, UTC hours, wrap-around aware. The **first hour of the window is grace** (the pause timer fires at `start:00` and the node takes a moment to stop), reported as a named skip rather than passed over silently — one hour of coverage traded for a canary that never cries wolf on a healthy pause. **Detect-only**: stopping the node here would fight the pusher's suppression and the recovery breaker. Deliberately its own module rather than an inverted predicate inside `pusher.py` — that file is the alerting hot path for all 35 app monitors, and a bug in a new branch there pages falsely on every app, every cycle. Exit 0 held-or-skipped / 1 `tdarr-pause-violated` / **2 could-not-assert** (manifest unreadable, no `pause_window` declared, unit state unreadable). Test override: `QFLIX_CANARY_TDARR_HOUR` injects the UTC hour, because otherwise the enforced branch is only reachable 4 hours a day, which in practice means never tested.
- `tdarr-healthcheck.sh`  — Tdarr's health-check pipeline actually produces successes. Three predicates: **engine sanity** (each library's configured scan engine must have a binary that exists — reds on tick one), **error ratio** of completed checks (20% warn / 50% fail, after a 20-check minimum), and **progress/stall** (queue non-empty + node running + no new completed check in 8 h = wedged). Added after the pipeline ran 100% dead and silent for 68 days: libraries defaulted to `handbrakescan` and HandBrakeCLI does not exist on this slot, so every check spawn-failed ENOENT while transcodes kept succeeding and masked it.
- `ucc-gate-stuck.sh`     — the UCC maintenance-gate **detector**, not the apps it gates. `lib/ucc.py`'s probe-error branch holds the prior `active` flag, and `lib/suppression.py` reads that flag on every webhook down-event — so a probe that merely can't reach the host silently disables auto-recovery fleet-wide. Found stuck at `consecutive_error=128` (~10.6 h); the 2026-07-29 fix caps the hold at 3 cycles and fails **open**. This is the independent second leg: `consecutive_error > 12` (~1 h — the cap stops the suppression damage, this catches detection itself going dark) or `active` continuously true ≥ 6 h (defense in depth against a *different* bug freezing the gate on). Reads `ucc-window.json` directly rather than importing `lib.ucc`, so it still fires if that module breaks. A missing state file passes — timer liveness is a separate concern.
- `dash-asset-integrity.sh` — whether the SERVED dashboard shell can actually **hydrate**, which `mobile-ux.sh` cannot see. Two independent predicates: every `/_app/immutable/*` reference extracted from the served HTML must resolve **200** from the process that served it, and the document's advertised `Content-Length` must match the bytes actually delivered. Added after the public board served a dead shell for ~22 h on 2026-07-29 with every monitor green: `build/` was rewritten (01:33, 03:31) over a node process up since 2026-07-08, and adapter-node hands static files to **sirv, which snapshots its file manifest ONCE at process start** — so 6 of the 10 referenced modules 404'd although every file was on disk at mode 644, and files rewritten in place kept the `Content-Length`/`ETag` sirv computed at boot, so browsers aborted with `ERR_CONTENT_LENGTH_MISMATCH` before `domcontentloaded`. Nothing caught it: qflix-dash's app probe is `/healthz` (answered by the stale process), and both `mobile-ux.sh` and `smoke-test.sh` only counted the server-rendered `data-qflix-dash` marker, which survives a total hydration failure. A third predicate covers the case neither of those catches: a 200 whose body **never arrives** (headers, then a stall) satisfies neither predicate — `received` is never a number — and would otherwise be counted as a healthy probe. The `Content-Length` leg is **corroborated by an immediate re-probe** before it is believed, because a stale sirv stat tuple lies identically forever while one cycling nginx worker produces a single truncated response, and restarting a healthy dashboard over wire noise would spend the whole 24 h self-heal budget on nothing. **Self-heal is narrow:** a 404 whose file *exists* under `~/.apps/qflix-dash/build/client/` is a stale in-process sirv manifest and gets one `systemctl --user restart qflix-dash` — breaker 1 per 24 h, held in a durable epoch latch that is **reserved before the restart is issued** (written atomically, read back) and released again on every path that turns out not to have issued it; if the latch will not persist the restart is *refused*, because a breaker that is not durable is not a breaker. Also suppressed inside the Monday 11:00-15:00 UTC window, refused if the unit itself entered active less than two timer ticks ago, re-verified by re-fetch afterwards, every attempt logged durably. A 404 whose file is **absent** is a partial deploy, and a stalled body is a wedged worker: both alert and do *not* restart, because a restart cannot fix either.

- `kometa-libraries.sh`   — every kometa-configured Plex library still exists in Plex (semantic config-drift guard)
- `kometa-deploy-drift.sh` — deployed kometa config.yml `libraries:` set matches what scripts/configure/55-kometa-install.sh would render (textual drift guard)

- `hardlink-integrity.sh` — cross-references qBit completed torrents against the media library by inode: hardlinked = a library file shares the torrent's inode; a **copy-mode regression** = no inode twin but a byte-identical library file exists at a *different* inode (storage genuinely doubled). Fails only when copy-mode imports exceed both thresholds **and** the orphan-excluded sample reaches `QFLIX_CANARY_HARDLINK_MIN_SAMPLE` (default 5); below that it passes as inconclusive. Protects against silent storage-doubling if *arr flips from hardlink to copy mode.

Detects the silent override→fallback degradation the newsletter itself never surfaces. ## Stage labels (failure messages on stderr → Kuma `msg=`)

- `seerr-up-fail` / `radarr-up-fail` / `sonarr2-up-fail` — the named API didn't return 200
- `seed-pick-fail` — a seed exists but its tmdb id couldn't be resolved. NOTE: an **empty but reachable** library (0 movies/series — e.g. the reaper aged out the last title) is treated as an **inconclusive SKIP → PASS** (`PASS: … SKIP: … up but 0 …`), not a failure — it's a content state, not a Seerr→*arr path fault. A genuine *arr outage still trips `*-up-fail` earlier.
- `seerr-push-fail` — POST /api/v1/request returned non-2xx/409 (or 409 with no recoverable id)
- `arr-not-populated` — externalServiceId stayed null after 30s of polling
- `verify-fail` — externalServiceId did not match the *arr's id for the seed
- `cleanup-fail` — DELETE request returned non-2xx (warned to stderr, probe still passes)
- `kometa-config-missing` / `kometa-config-parse-fail` — kometa-libraries / kometa-deploy-drift: can't read/parse config.yml
- `plex-up-fail` / `plex-libraries-fetch-fail` — kometa-libraries: Plex API unreachable or no library list
- `library-drift` — kometa-libraries: at least one kometa-configured library doesn't exist in Plex
- `install-script-parse-fail` — kometa-deploy-drift: can't read the install script's library list
- `deploy-drift` — kometa-deploy-drift: deployed config's library set differs from what scripts/configure/55-kometa-install.sh would render
- `log-stale` / `log-missing-<app>` — stale-log-watchdog: a timer-driven app's log file mtime exceeds its expected cadence, or the log is missing entirely
- `library-empty` / `qbit-no-completed` / `hardlink-regression` — hardlink-integrity: no scanable videos under the media roots; qBit reports completed torrents but none resolve to on-disk files (data dir nuked / mount gone); or copy-mode imports (`detached`) exceed `MAX_DETACHED`n **and** `MAX_DETACHED_PCT`% over the orphan-excluded sample
- `bazarr-profile-dangling` / `bazarr-profile-unset` / `bazarr-no-languages` / `bazarr-ingest-stalled` —
  `bazarr-ingest.sh`: the instance's configured default profile does not exist in its DB (every
  insert will FK-fail), a default is enabled with no profile id at all, no language is enabled so
  nothing can be subtitled, or the *arr holds items the Bazarr side holds none of. Exit 2 covers the
  cases where the canary asserted **nothing**: `bazarr-db-unreadable`, `bazarr-config-unreadable`,
  `bazarr-db-query-fail`, and `bazarr-ingest-inconclusive` (an *arr could not be reached, so
  "nothing is missing" would be trivially true). A fired predicate outranks an inconclusive leg —
  proving something is broken reports exit 1 even when another probe could not be evaluated.
- `plex-up-fail` / `transcode-api-fail` / `prefs-api-fail` — plex-transcoder: Plex /identity non-200, or transcode/prefs endpoint hung or non-200
- `dash-*` — dash-asset-integrity: the served shell references an asset the running server will not serve, or the document's advertised `Content-Length` disagrees with the bytes delivered. The two faults carry **distinct** labels because they need different responses: a 404 whose file is present on disk is a stale in-process sirv manifest (restartable), a 404 whose file is absent is a partial deploy (not restartable), a 200 whose body never arrives is a stalled worker (not restartable), and the self-heal has its own labels for suppressed-by-the-Monday-window, refused-by-the-24h-breaker, refused-because-the-breaker-latch-will-not-persist, refused-because-the-unit-just-started, and issued-but-re-verification-still-failing. The script header carries the authoritative label table and the `QFLIX_CANARY_DASH_*` env overrides — read it there rather than duplicating the strings here, since this canary is the one that *acts*.
- `digest-stale` / `digest-missing` / `digest-malformed` / `digest-empty` — newsletter-digest-stale: the digest branch's `week_of` isn't fresh at Monday send time, the file/branch 404s or is absent, the JSON fails to parse (or `week_of` is missing/non-string), or `html` is blank. Only evaluated inside the Monday 14:15-24:00 UTC send window — outside it, and on a pure transport failure after 3 retries, the canary passes (`not-in-eval-window` / `digest-check-inconclusive`) rather than alerting.

- `timer-missing` / `timer-inactive` / `timer-stuck` / `timer-read-fail` — `timer-liveness.sh`: a job
  declared in `manifest/jobs.yaml` is not installed on the box, is loaded but not active (it will
  never fire again), or is active with nothing scheduled on either clock. `timer-read-fail` means
  the ledger or systemd could not be read at all. A last run that exited non-success is reported as
  `PASS-WARN`, not a failure — a canary legitimately exits non-zero to report ITS subject down, and
  that already has its own monitor. Jobs whose intended terminal state is "gone" opt out with
  `may_be_absent: true` in the ledger.

- `prowlarr-appsync-missing` / `prowlarr-appsync-magnet-pref-off` — `prowlarr-app-sync.sh`: an
  indexer Prowlarr intends to sync (enabled **and** tag-intersecting **and** category-intersecting)
  is not present in that *arr, or a diagnosed indexer still prefers the proxy download URL over its
  magnet. Both are exit 1. The BROKEN set is exit 2 and each names its stage:
  `prowlarr-appsync-no-apps` (zero applications — "nothing is missing" would be trivially true),
  `prowlarr-appsync-no-indexers`, `prowlarr-appsync-prowlarr-down`, `prowlarr-appsync-arr-down`,
  `prowlarr-appsync-unknown-app`, `prowlarr-appsync-config-missing`, `prowlarr-appsync-probe-error`.
- `plex-unmatched-stuck` — `plex-unmatched.sh`: at least one Plex episode has sat on a `local://`
  guid past the grace window. Exit 2 covers the cases where the canary asserted **nothing**:
  `plex-sections-unreachable` / `plex-section-unreachable` (Plex or a section did not answer),
  `plex-no-show-sections` (nothing to scan — an empty section list is not a clean library),
  `plex-section-truncated` (a section declared `totalSize`>0 and handed back no `Metadata`, i.e.
  empty-because-broken wearing empty-because-clean's clothes), `plex-unmatched-config-missing`.
  A clean run prints `plex-unmatched-clean` and always reports the suppressed sub-grace count.
- `rea-not-auditing` / `rea-unreached` / `rea-verdict-stale` — `rea-liveness.sh`: the workstation
  audit's last run failed, it has not reached the box inside the 336 h cap, or it is still reaching
  the box while its last verdict has frozen (the wedge a heartbeat-only signal cannot see). Exit 2
  is reserved for "this canary cannot assert anything": `rea-heartbeat-absent` (the writer half is
  not wired in `qflix-rea.ps1` — nothing is watching REA, said out loud rather than passed over),
  `rea-heartbeat-empty` / `rea-heartbeat-malformed` / `rea-heartbeat-unreadable`, and any outcome
  token the canary does not recognise, because a watchdog that green-lights vocabulary it does not
  understand is not a watchdog.

## Exit codes

- `deploy-drift` / `deploy-orphan` / `src-missing` / `fetch-failed` — `deploy-drift.sh`: a
  deployed file under `~/scripts` differs from `origin/master`, or exists on the box with no
  counterpart in git at all. The second direction is the sharper one: an unfinished
  decommission, or code running with no source of truth. `fetch-failed` is reported rather
  than passed, because comparing against a stale ref makes everything look clean — which is
  the exact failure this canary exists to prevent.
- 0 — pass; stdout has the `PASS: ...` line (or, for newsletter-digest-stale, `digest-fresh ...` / `not-in-eval-window ...` / `digest-check-inconclusive ...`) that Kuma stores as `msg=`
- non-zero — fail; stderr's `STAGE=... msg=...` line becomes Kuma `msg=`

- `stream-cap-liveness.sh` — whether the two **crontab** entries that enforce the per-member concurrent-stream cap (`kill_stream.sh --max 4` and `stream_stats.sh`, both every minute) are still running. `kill_stream` is member-facing *enforcement* and had **no dead-man of any kind**: not among the Kuma monitors, not among the push tokens, no self-push in either script, and structurally unreachable by the C-01 ledger — whose boundary is systemd timers plus (since 2026-08-06) declared installer units, while **crontab is a third scheduling plane neither leg enumerates**. The only freshness assertion in the repo lived inside `smoke-test.sh`, which no timer runs. If the crontab is dropped by a slot rebuild (`59a-plex-stream-crons-install.sh` records that this already happened once), or the plexapi venv breaks, or `plex.token` expires, the cap simply stops applying and nothing goes red. **Detect-only, and deliberately not a push bolted onto `kill_stream.sh`** — that edits the enforcement path, where a bug does not merely mis-report but can stop the cap working or wedge a per-minute cron; a separate observer can only ever mis-report, which is the failure mode you want there. The clock is the **writer-stamped `ts` embedded in each artefact**, never the file mtime: mtime-freshness is a named defect class here (C-04, discovered 2026-07-25) and both artefacts carry their own epoch, so the content clock is available. `kill-history.json` is appended on **every** run, not only on kills (`kill_stream.py:76-77`), so it is a true liveness signal — verified by sampling both files 75 s apart and watching each advance by exactly 60 s. **Privacy is load-bearing, not incidental**: `state.json` holds member Plex usernames, what they are watching, and per-user counts, so this canary parses *only* the numeric `ts` fields and emits *only* ages — never a username, title, per-user count, or even the total active-stream count, because a Kuma `msg=` is a durable forwarded string and a stream count is consumption. Threshold 900 s tolerates ~14 consecutive `flock` skips on a contended box while still catching a dead cron inside a quarter hour. Exit 0 / 1 `stream-cap-stats-stale` \| `stream-cap-kill-stale` / **2 could-not-assert**. Override: `QFLIX_CANARY_STREAMCAP_DIR`, `QFLIX_CANARY_STREAMCAP_MAX_AGE_S`.

- `cron-liveness.sh` — whether the live **crontab** matches `manifest/jobs.yaml`, in **both** directions. QFlix schedules work on three planes — repo-tracked systemd timers (`timer:`), installer-generated timers (`unit:`, covered 2026-08-06), and the user crontab — and the third was the last one outside the dead-man boundary. It was not merely unmonitored but *inexpressible*: a crontab line has no unit name **and** no file in git, so neither existing field could name one, leaving all ten lines unadjudicated and unadjudicat**able** — including `kill_stream.sh --max 4`, which is member-facing enforcement of the per-member concurrent-stream cap. `cron:` entries now declare them, and this is the LIVE half of that: the offline C-01 detector reads the declarations and demands a written dead-man answer for each, but it runs against git and cannot see the box, so it can never notice a line that was **dropped** (`59a-plex-stream-crons-install.sh` records that a slot rebuild already wiped these once, silently) or one **added** without adjudication. `cron-declared-missing` catches the first; `cron-unclaimed` catches the second — and that second direction is what catches the *next* hand-added cron before it becomes another invisible member-facing dependency. Matching is on the `cron:` command substring **only, never on `schedule:`** — that field is documentation, and if it drifted from the real crontab expression this check would start failing for a cosmetic reason. Comments, blanks and `VAR=` assignments are configuration rather than scheduled work, so they are skipped, counted and named. Exit 0 / 1 / **2 could-not-assert**, and that includes the case where the ledger declares **zero** cron jobs: an empty declaration set would make "everything declared is present" vacuously true, which is the empty-because-broken-reads-as-clean trap this repo keeps closing. Deliberately its own canary rather than a leg of `timer-liveness.sh` — different mechanism, different failure vocabulary (loaded/active/next-fire has no crontab analogue), independently swappable, the same reasoning that made `prowlarr-app-sync` a second canary rather than a third probe.

- `entitlement-service.sh` — whether the **entitlement API the access gate reads** is alive, authenticated, honouring its response contract, and still carrying patron data. `manitoba-maint-entitlement` already has a dead-man ("QFlix Entitlement Gate", 15-minute timer with a 1h heartbeat override), but that watches the *gate*, and the gate is built so a broken *service* is invisible from it: `lib/entitlement.py` grades every outage, every 401, every 5xx and every malformed body as **UNKNOWN**, and UNKNOWN neither grants nor revokes. That asymmetry is the load-bearing safety property of the whole design — an entitlement API outage must **freeze** this system, never **drain** it, because fail-closed applied to revocation is a mass-eviction button wired to the least reliable component in the stack. Its consequence is a gate that keeps running, keeps pushing green every 15 minutes, and quietly stops provisioning anybody. **Frozen is the safe direction, not a safe state**: a frozen gate means paying members are never granted access, and nobody writes in to report the access they did not get. Four legs, escalating: `/healthz` returns 200; an authenticated lookup does not 401/403 (**a rotated key is otherwise indistinguishable from an outage**, and would send the operator to restart a service that was never broken); the 200 body is a JSON object carrying a **boolean** `entitled` (the client already refuses to grade a 200 without it — "a contract violation, not a no" — precisely so a server-side refactor cannot silently revoke everybody, and that refusal is correct *and* silent); and a sync **oracle**. The oracle is the only leg that can catch a dead Patreon projection, because the service's answer for a patron it has *lost* is byte-identical to its answer for someone who never subscribed — `{"entitled": false, "reason": "unknown"}`. It builds its known-good set from `lib/access_state.py`'s `last_entitled_at`, which exists because "the entitlement API is a projection of NOW with no history at all", and discriminates on `reason`: `status=former_patron` is an ordinary cancellation and no fault, whereas `reason=unknown` for an account that was **demonstrably entitled before** means data was lost. One such account could be an upstream email change; **all** of them at once is a wiped projection — and since it arrives as a well-formed 200, the UNKNOWN grading never engages and an armed gate would read every one as a revoke. Probes leg 2 and 3 on a synthetic **RFC 2606 `.invalid`** address so no member address enters a public repo, a Kuma `msg=`, or journald; leg 4 must read real addresses from the state file at runtime and masks every one before printing. A **dormant** oracle (nobody has ever been entitled) is a documented **pass, not an exit 2** — the empty-because-broken rule targets a check made *vacuously true by a broken input*, and with zero patrons there is no patron to forget, so there is no fault the leg could miss; every PASS message names which of the two it is, so a permanently dormant oracle stays visible rather than reading as a satisfied check. An unreadable or unparseable `state.json` **is** exit 2, because then "zero ever entitled" is empty-because-broken and the oracle is blind rather than dormant. Exit 0 / 1 `ent-service-down` \| `ent-key-rejected` \| `ent-lookup-http` \| `ent-contract-violation` \| `ent-sync-forgot-everyone` / **2 could-not-assert**.

- `unstick-rate.sh` — whether the **autonomous unstick has gone haywire**. `qflix-collect.py`'s `act_on_candidates()` calls `unstick.py`, which does `DELETE /queue/{id}?removeFromClient=true&blocklist=true` — deleting the download, removing it from the client, **and blocklisting the release so the *arr will not grab it again**. It is the most destructive autonomous action on this stack, it is member-facing (a blocklisted release is content that does not arrive), and on 2026-08-07 it destroyed **ten legitimate releases in one run** with no alert, no Kuma red, and nothing anywhere for the operator to see — the only thing that stopped it at ten was `MAX_ACTIONS_PER_DAY`, and that cap resets at 00:00 UTC. **Deliberately watches the ACTION, not the rule**: a guard on the rule catches only the failure it was written for, whereas watching the destructive outcome catches every cause, including ones nobody has thought of. Reads the durable audit trail the actor already writes (`~/.opt/qflix-collect/events/YYYY-MM-DD.jsonl`, one JSON line per action). WARN at 3 actions/day, FAIL at 5, and **always** on reaching the daily cap — hitting the cap means the system wanted to do *more* than it was allowed, which is precisely what a runaway rule looks like. Cap-reached is tested **separately from the numeric threshold on purpose**: the cap is operator-tunable, so raising it must not silently raise the alarm with it (verified — with the cap at 50, ten actions still fails on `rate-high`). Not "alert on any action": unstick exists to act unattended, and a canary that reds on every legitimate use gets muted, which would leave this exactly as blind as it was before. Exit 0 / 1 `unstick-rate-high` \| `unstick-cap-reached` / **2 could-not-assert** — a missing events dir or a single unparseable line exits 2 rather than undercounting, because silence was mistaken for health here once already. Overrides: `QFLIX_CANARY_UNSTICK_WARN`, `QFLIX_CANARY_UNSTICK_FAIL`, `QFLIX_CANARY_UNSTICK_EVENTS`.
